## Context

- Patch 11 of `third_party/ruby-1.8.7/PATCHES.md` (`symbol-ids-ruby-181`): `rb_intern` looks
  a name up in `vkxp_symbol_table` (generated by `build.rs` from
  `data/symbols.startup.txt`) and gives it the number found there; other names get
  provisional numbers until `ruby_vkxp_mark_game_scripts`, and from then on continue at
  `last_id`, which starts at `VKXP_LAST_MEASURED`, the largest counter of the table (2023
  for XP, so the first new local variable is `2024 * 8 + 1 = 16193`).
- `Interpreter::start(Options)` (`src/interp.rs`) starts the interpreter thread;
  `Options` has the stack size and the script name. One process holds one interpreter.
- Measured on the original runtime of VX (report `vx-v1-REPORT.md` in
  `ref/tools/oracle/measurements/`, outside the repository; probe
  `vx-v1-symbols-probe.rb`):
  - 1996 names before the first game script, all printable ASCII; the largest number is
    16081 (`s`), counter 2010.
  - The first script `zz_first = 1; zz_second = 2` gives `:zz_first.to_i` 16089 and
    `:zz_second.to_i` 16097; further new local variables 16105, 16113, 16121. So the rule
    of XP holds: the sequence continues after the largest counter of the table.
  - The same on `RGSS202E.dll` 2.0.2.1 and on the file of version 2.0.0.1.
  - `RUBY_VERSION` is 1.8.1 with the release date of XP's; `rand` after `srand`,
    `String#hash` of the nine strings of `tests/hashes.rs` and `1.5.hash` (53405) equal
    those of XP.

## Goals / Non-Goals

**Goals:** a caller can start the interpreter with the numbers of RGSS2; nothing changes for
a caller that does not ask.

**Non-Goals:** choosing the table in the program (needs the runtime value of another
change); the names the binding interns for RGSS2 classes; any other difference between the
two runtimes' interpreters.

## Decisions

- `build.rs` generates one header with both tables, each with its largest counter, from
  `data/symbols.startup.txt` and `data/symbols.startup.rgss2.txt`. The checks it makes
  today (format, printable names, no name twice) apply to both files.
- C side: `ruby_vkxp_select_symbols(int)` sets which table `vkxp_measured_id` searches and
  where `last_id` starts. It is called before `ruby_init`, because `ruby_init` interns
  names. A call after the first `rb_intern` is a bug of the caller and ends in `rb_bug`.
  Without a call the table of RGSS1 is used.
- Rust side: `Options` gains `symbols: SymbolTable`, an enum `Rgss1` (the default) and
  `Rgss2`. The start of the interpreter thread applies it before it initialises Ruby.
- The scope check that calls `rb_bug` when a table number disagrees with the name's scope
  stays and applies to the chosen table.
- Tests of RGSS2 are a test file of their own, because a test process has one interpreter:
  the table names, the first new numbers, the order of instance variables computed as the
  test of XP computes it.
- Patches shared and by runtime. By runtime: the start-up symbol table (this change).
  Shared, on the evidence above: the random numbers, `String#hash`, `Float#hash`. Shared by
  assumption, since both originals report the same Ruby version and date, and to be probed
  on the original of VX before a milestone relies on them: class redefinition with another
  superclass, the regular expression behaviours, the range that starts with a class, and
  the remaining recorded patches. `PATCHES.md` gets a short section that says this.

## Risks / Trade-offs

- A table of a third runtime will need the same again; the selection takes a number, not a
  flag, for that reason.
- Selecting after start-up cannot be supported: numbers already given would be wrong.

## Follow-ups

- The program passes the table of the detected runtime at its two calls of
  `Interpreter::start`.
- `1e300` and other float literals near the limit read as `Infinity` on the original of VX
  (`1e290` is finite); what vkxp and the original of XP give was not compared on the same
  day. To be measured on both originals.
- The assumptions of the last decision, probed on the original of VX.
